## 2. 产品语义

职责链固定为：

```text
机构发起
→ 后端在已发布模板边界内确定性生成并自动提交
→ 平台医学专家结构化审核
→ 用户本人或有效代理确认
→ 接受后方案 ACTIVE
```

- 机构人员不能声明资格、READY、评估完成、高风险解除或生成完成。
- 平台端不提供具体客户“生成方案”按钮。
- 平台专家只能 `APPROVED / NEEDS_CORRECTION / REJECTED` 加获批原因码，不能编辑方案正文。
- 一期不出现 LLM、AI自由生成、置信度、诊断、处方、药物调整、价格、BOM、支付或结算。
- 主健管师不发起、编辑或审核方案；健管师 APP UI 不在本任务。

## 4. 状态与交互冻结

| 服务端状态 | 可见业务语言 | 客户端动作 |
|---|---|---|
| `REQUESTED / GENERATING` | 方案生成中 | 查询进度，不显示正文 |
| `GENERATION_FAILED` | 生成未完成 | 展示安全原因与刷新；不伪装成功 |
| `IN_REVIEW` | 医学专家审核中 | 机构只读；专家可领取 |
| `NEEDS_CORRECTION` | 需补正 | 显示结构化原因及新版本状态 |
| `APPROVED / USER_DECISION_PENDING` | 已审核，待用户确认 | 机构只读跟进 |
| `REJECTED` | 审核未通过 | 只读原因 |
| `NEEDS_EXPLANATION` | 用户需要解释 | 机构只读；不提供健管师APP动作 |
| `DECLINED` | 用户已拒绝 | 只读 |
| `ACTIVE` | 执行中 | 显示当前活动方案与历史版本 |

- 所有 mutation 使用 `Idempotency-Key`；网络不确定时复用原 key。
- `COMMIT_OUTCOME_UNKNOWN` 后只查询状态，不能换 key 或自动重发。
- 409 后刷新并要求用户重新确认，不自动重放 mutation。
- 202 只代表请求已受理，不代表方案生成、审核或激活完成。
- 提交期间禁用相关按钮，发布、退役、审核决定均二次确认。

## 5. 错误映射

- 401：登录失效并回到登录流程。
- 403：角色、tenant、claim 或用户范围不足；不泄漏对象存在性。
- 404：当前范围内不存在或安全隐藏。
- 409：展示稳定业务阻断码；刷新，不自动重放。
- 422：字段、UUID、枚举或 extra 字段错误。
- 429：操作频繁，保留用户上下文。
- 503 `COMMIT_OUTCOME_UNKNOWN`：结果未知，查询确认。
- 其他 503：依赖暂不可用，不包装成成功或业务冲突。

因此本阶段规则为：

2. 页面组件状态使用 Vitest 内明确标识的开发测试替身；替身不能作为真实 HTTP 证据。
