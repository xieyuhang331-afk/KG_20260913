## 阻断诊断与关闭

原始现象为真实浏览器创建邀请返回 HTTP 503 `DEPENDENCY_UNAVAILABLE`，列表无新记录。

脱敏分层复现确认：

- 前端 payload 与 OpenAPI 一致：`phone`、`expires_in_minutes`、`Idempotency-Key`；
- 使用旧 Disposable 控制器时，数据库权限初始化状态受完整迁移生命周期测试影响；
- 使用正式 Migration 后一次性建立测试 application baseline，不把测试用例作为运行环境 provisioning 步骤；
- production service 直接调用：`SUCCESS / INVITED`；
- 真实登录：HTTP 200；
- 真实创建邀请：HTTP 201；
- 邀请列表：HTTP 200，并出现新记录；
- 真实撤销邀请：HTTP 200，页面展示“已撤销”；
- 相同 Idempotency-Key 重放：返回同一资源；
- 陈旧 `expected_version`：HTTP 409 `THERAPIST_VERSION_CONFLICT`。

结论：原 503 属于 Disposable 验收控制器的初始化顺序问题，不是前端请求、后端生产代码、Migration 合同或 RabbitMQ/Outbox 缺陷。阻断已关闭。
